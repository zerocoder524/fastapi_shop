# Складская логика заказов

`POST /orders` теперь:

- блокирует строки выбранных товаров через `SELECT ... FOR UPDATE`;
- проверяет, что товары существуют и активны;
- проверяет, что остатка достаточно для каждой позиции;
- не позволяет заказать товар с остатком 0 или количеством меньше запрошенного;
- уменьшает `stock_quantity` только после успешной проверки всего заказа;
- создаёт `orders` и `order_items` и списывает остатки одним `COMMIT`;
- выполняет `ROLLBACK` при любой ошибке.

Новая Alembic migration не нужна, потому что структура БД не меняется.

## Тесты в Swagger

### Недостаточный остаток

```json
{
  "items": [
    {
      "product_id": 1,
      "quantity": 1
    }
  ]
}
```

Если у товара `stock_quantity = 0`, ожидается `409 Conflict`.

### Успешный заказ

```json
{
  "items": [
    {
      "product_id": 2,
      "quantity": 2
    }
  ]
}
```

Если было `12`, после успешного `201 Created` должно стать `10`.

### Проверка атомарности

```json
{
  "items": [
    {
      "product_id": 1,
      "quantity": 1
    },
    {
      "product_id": 2,
      "quantity": 1
    }
  ]
}
```

Если у первого товара остаток 0, заказ отклоняется целиком и остаток второго товара не уменьшается.
